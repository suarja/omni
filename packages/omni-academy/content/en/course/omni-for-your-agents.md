## Open the local MCP door

Omni exposes a local MCP server for identified harness sessions. It can answer from registered projects, marketplaces, and Activity evidence.

Open `Settings` in the canvas rail and find `Agents`.

- The setup is local-only.
- The page names the detected harnesses.
- The agent row’s `Check connection` reports its last real Omni call.

## Choose a harness deliberately

Choose `Connect` beside a detected, disconnected agent. Connect each agent separately.

The selection controls the scope of the generated plan; it is not a global switch.

- Read which agent the confirmation names.
- Treat each harness as a separate projection.
- Read the connection summary before its final `Connect`.

## Consent before any write

The connection confirmation describes the tool, skills, and file protection. It does not list file-level diffs. An agent request can be consented in conversation or reviewed in Omni.

The final `Connect` prepares and applies the installation.

- Read the summary before `Connect`.
- Reject or postpone a plan that is not understood.
- The applied result becomes a receipt.

## Read and restore the receipt

Activity records completed operations and their results. A later restore compares current content with the original receipt.

This keeps local agent work auditable without making the MCP door a cloud dependency.

- Open `Review` for pending requests and `Activity` for completed work.
- Use an eligible `Undo` in Activity and read its reverse preview.
- Use `Check connection` in the agent menu to read last-call evidence.

## Before you act

Start with the observed page, not an assumption about the filesystem. The current route and its head tell you which target Omni has in scope.

- Read the page title and the active tab.
- Prefer the named action over a shortcut.
- Keep the local path available for comparison.

## Check the boundary

Every preview is read-only until its approval control is chosen. A blocked or unavailable state is evidence that needs a different decision.

- Treat a missing root as unavailable, not empty.
- Treat a conflict as a stop condition.
- Keep the harness name beside the path.

## Keep the trail

After a write, Activity holds the operation history. The receipt and Git commit complement each other and make a later restore deliberate.

- Read the files in the receipt.
- Compare later edits before restoring.
- Return to the source of truth for the next change.

## A weekly check

Re-open the source and project when your harness conventions change. This small review keeps the next operation tied to current local evidence.

- Refresh the observed root.
- Read the changed paths.
- Choose one deliberate next action.
